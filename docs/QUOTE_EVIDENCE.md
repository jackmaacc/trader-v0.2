# Quote decision evidence

The existing paper breakout and portfolio runner source now captures entry qualification, signal-price checks, submission-time qualification, retrieval failures, and every holding quote decision. No runner was started during this repair.

- Entry checks before a cycle write `quote_decisions.jsonl` under that run directory. The single-position submission check uses the same file; portfolio submission checks use the cycle journal. Both capture accepted and rejected checks. Each record saves symbol, feed, raw payload, receipt and decision times, source/cache age, effective validation policy and exact reasons. Signal rejections distinguish `bid_not_above_breakout` and `entry_above_signal_band`. Retrieval failures retain exception class and numeric HTTP status where available, never exception text.
- Holding checks write `holding_quote_accepted` or `holding_quote_rejected` into the existing durable cycle journal, before using the quote. Accepted decisions identify hold, target, stop, recovery expiry, or waiting for a slightly future event. Stop/target decisions include thresholds. The first and latest failure survive bounded recovery in holding state.
- Diagnostic shadow rows retain a quote diagnostic even for a missing, malformed or wrong-symbol quote; these diagnostics are not broker authorization.

Existing entry limits remain 5-second source freshness, nonfuture event time, 10-bps spread, positive uncrossed prices and ask at least $1, without a size gate. Receipt diagnostics are retained separately; they do not introduce a new entry gate. Existing legacy holding limits remain 10-second source freshness and up to 250 ms future clock skew, with positive uncrossed prices and no new size/spread gate. A slightly future quote is recorded and rechecked after waiting before it can trigger an exit. Recovery validation keeps its stricter supplied/default limits and the existing legacy upper bounds. SIP validator defaults are unchanged.

Validation takes a deep copy and both evidence and downstream holding/entry decisions use that copy. Ordinary JSON payloads are preserved unchanged. Nonstandard NaN/Infinity floats become explicit `nonfinite_float` tags inside the strict-JSON record, with the original JSON token representation retained in `raw_payload_json` and identified by `raw_payload_encoding`. Offline replay restores this field with `json.loads` before constructing `QuoteEnvelope`; the policy snapshot supports deterministic revalidation.

Serialization or storage failure prevents using that quote. Existing journal capacity is unchanged: 1,024 slots in the single runner and 2,048 in portfolio workers, each 4,096 bytes. A normal 15-minute hold at three-second checks adds roughly 300 quote records plus existing order/other records; recovery/future waits can add more. There is no promise that arbitrary payloads or abnormal retry rates fit. Slot overflow or exhausted capacity fails closed, preserving existing protection/reconciliation behavior. Regression tests exercise both failures using real reserved journals.

## Historical incident limit

`tests/fixtures/quote_incidents.json` is explicitly synthetic category reproduction, not an archive of historical failure payloads. The historical second-portfolio report states that the rejected XOM and TJX quotes and individual failed conditions were not saved. Their causes remain undetermined; the XOM stale and TJX future fixtures exercise possible categories only. KLAC retains a historical last bid of $182.31, entry $187.850633, stop $185.97, exit fill $187.94 and local `stop_level` decision; its complete trigger quote, ask and event/receipt times are unavailable. The fixture invents those missing fields to reproduce the local stop branch and cannot establish a market move or feed cause.

Source evidence: `artifacts/paper_portfolio_until_close_2026-09-23_02/REPORT.md` and `artifacts/paper_portfolio_until_close_2026-09-23/cycles.jsonl`. Historical artifacts are unchanged. Missing historical payloads cannot be reconstructed by this repair. HTTP request bodies unavailable after a retrieval exception cannot be recovered; those events retain a missing raw quote and the retrieval failure category.
