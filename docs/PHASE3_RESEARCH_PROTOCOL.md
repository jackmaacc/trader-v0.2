## Window and data eligibility

Reserve October1,2026–September30,2027 as a future envelope. The primary sample is **the first126 actual relevant exchange sessions** for equities/options, and **October1,2026–February3,2027 inclusive (126 UTC days)** for crypto. The remainder of the envelope is reserved and cannot provide an automatic extension or second chance to pass. Before registration, archive the exact exchange calendar dates/hash and verify all126 sessions fit the envelope. Observations begin only after a timestamped design/code/data-readiness registration before October1. A late or incomplete registration loses this prospective claim; choose a newly frozen future window, preserve the failed attempt, and never backdate evidence.

All dates already inspected are consumed. Warmup bars before October1 supply features only and earn no test performance. Archive event time and actual receipt time; revised history cannot change a prior decision. For equities, completed inputs must arrive before09:20 Eastern next session. Options use actual09:35 SIP/OPRA observations; missing/stale or invalid quotes skip entries and retain pending exits. Crypto uses00:05UTC execution eligibility and the exact availability rules in JSON. Data gaps are retained as gaps; missing execution prices are never forward-filled.

The module's design-freeze timestamp uses the host clock and can be injected for tests. A content hash is not a trusted timestamp, signature, tamper-proof archive, or evidence of prior independence. Formal prospective registration still needs independent review, an externally retained dated receipt, immutable source snapshots, actual executable adapter fingerprints, exact calendar and ledger readiness. This is not a second qualification framework bypassing the legacy reviewer.

## Common accounting and rejection

Each candidate and control starts with separate$100,000 cash, zero legacy holdings and no cash flows. Reconstruct cash, units, distributions/receivables, fees and marked equity independently; no spending unpaid distributions. Carry real ownership through missing quotes. Open-position terminal bid valuation is an accounting mark, not a natural exit or an extra closed episode. Report average/max exposure, turnover, concentration, gross-before-cost economics, net trading P&L and business P&L after known overhead. Unknown overhead prevents qualification.

Charge actual comparator turnover, fees, spread/impact and dividends. The primary equity/crypto control matches lagged **exposure**, not volatility; the options control matches lagged **delta-notional**, not gamma, vega or tail risk. No full-window realized-volatility rescaling. If specified95%/10% match validity fails, label comparison inconclusive. Passive controls are reported alongside the primary; never select the favorable comparator afterward. Report before-cost paired performance so control rebalancing costs cannot be mistaken for predictive alpha.

Require126 paired observations and30 organic closed episodes. Reject nonpositive before-cost expectancy, nonpositive base excess, nonpositive stressed/delayed net economics, drawdown above5%, or failure after removing the five best daily excess contributions. Quality/provenance/coverage failures and insufficient sample mean **inconclusive**, not pass. Full-window paired stationary bootstrap uses100,000 resamples, expected blocks5 and10, deterministic seed20261001 and one-sided alpha0.05/6. Jointly resample base/stress/delay vectors to retain cross-series dependence. Require positive lower bounds at both block lengths; no interim efficacy peeks, winner selection or optional extension. Report symbol contributions and open P&L separately from episode expectancy. These are specified gates; no statistical outcomes have been computed.

The daily equity research halt blocks entries after1% UTC-day loss; crypto retains its3% entry-only baseline halt. Neither forces portfolio liquidation at an arbitrary daily threshold. Daily observations cannot certify intraday risk compliance. Options reserve full premium as planned loss; failed exit/exercise/assignment handling blocks lifecycle qualification. Existing runner policy is unchanged.

- **All:** implement adapters on the existing shared accounting engine, parity-test against these exact rules, review independent reconstruction and archive immutable receipts before any outcome evaluation. Known business overhead and independent review remain outstanding. No implementation or collection is implied by writing these designs.

## Design hash utility

`trader_engine.research.protocol_registry` validates required track structure, rejected-candidate inventory, fixed sample/inference constraints and false execution authority. It hashes canonical JSON and named source files. `freeze_registry(registry, new_receipt_path, sources)` writes a new0600 file exclusively, refuses existing destinations/symlink paths and refuses freezing at or after the reserved start. Include this document, the registry source, and each actual adapter file in the named source inventory when available. `verify_registry(receipt_path, registry, sources)` rejects changed content or source inventory. It returns only design integrity, with prospective registration and execution authority explicitly false.

Validation is structural: prose presence is not proof of causal implementation, appropriate economics or executable data. Tests do not establish an edge. A receipt should be preserved with the reviewed commit and later registration evidence, rather than overwritten. There is no automatic broker, scheduler or qualification side effect.
