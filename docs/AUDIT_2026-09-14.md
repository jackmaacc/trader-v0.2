**1. P1 — Learned states leak future information in the standard historical backtest. Reproduced.**

[Dataset preparation](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/research/context.py:124) fits the state model on the entire history before historical signals are generated. Quantile boundaries, medians, scaling, PCA, clusters, and sparse-state merges therefore incorporate future data. A two-bin probe changed five of the first ten state labels when ten later observations were added. The separate walk-forward runner fits within training windows, which is better; that does not repair the standard workflow. Fit each learned component only on the history available at the decision time. Add a future-perturbation test requiring unchanged earlier states, signals, and orders.

**2. P1 — Opening position size and stop use execution-bar ATR. Reproduced.**

[Entry risk check](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/backtest/engine.py:147) and [initial stop](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/backtest/engine.py:433) read ATR from the bar whose open fills the trade. ATR includes that day's high and low, which are unavailable at the open. Changing only that ATR from 1 to 10 changed an exit from stop-loss to end-of-test in the probe. Carry the last completed bar's ATR in the order; use it for sizing and initial protection. Changes after the opening instant must not alter the opening quantity or initial stop.

**3. P1 — Final liquidation is omitted from the equity curve. Reproduced.**

[Terminal accounting](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/backtest/engine.py:320) appends a post-liquidation record at the same timestamp and then keeps the first duplicate. Trades include the final fees, while equity and performance retain the pre-liquidation value and open positions. A $10,000 flat-price test ended at $9,900 after fees but reported $9,950 and one open position. Replace the final snapshot after liquidation and assert `final equity = initial capital + sum(realized P&L)` when flat, with zero open positions and exposure.

**4. P1 — Opening risk checks use stale marks and miss gap losses. Reproduced.**

[Event processing](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/backtest/engine.py:76) values holdings at previous closes before new entries; current marks update only after entry processing. A portfolio losing 10% at the open still filled another entry despite a configured 3% daily-loss threshold. Mark existing holdings at executable opening prices before risk checks, process opening exits/protective gaps, and recheck post-fee exposure. Test gaps with multiple simultaneous entries and exits.

**5. P1 — Daily loss protection has no persistent halt state. Code finding.**

[Daily-loss logic](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/risk/engine.py:44) is a point-in-time ratio. It can permit trading again after recovery and does not record a session halt or cancel queued entries. The next day's equity baseline is reset in [the backtest loop](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/backtest/engine.py:79). Define whether the rule means entry suspension or liquidation, latch a breach through the session, cancel affected entries, and use explicit exchange/session boundaries. A test should breach, recover, and verify no entry resumes before the configured reset.

**6. P1 — State-quality history joins unrelated learned states. Code finding.**

[Quality grouping](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/research/quality.py:66) keys on asset class and state/transition label, omitting symbol and fitted-model identity. Independently fitted `cluster_00` or bin labels need not represent the same market condition across symbols, folds, or the train-plus-validation refit in [walk-forward preparation](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/research/walk_forward.py:131). Quality scores can be transferred to unrelated states. Version state definitions and scope learned-state statistics to symbol and fitted model, or explicitly align stable state semantics. Test label permutations and refits; arbitrary label renaming must not change economic decisions.

**7. P1 — Model selection reuses test results as the selection target. Code finding.**

[Parameter sweeps](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/research/sweeps.py:70), [model comparisons](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/research/model_comparison.py:255), and exit/policy/ablation ranking select using `mean_test_*` results. Individual forward folds may be chronological, but the selected winner's reused test score is not an independent final evaluation. Use inner chronological validation for all tuning and an untouched outer evaluation, then one final holdout for the frozen strategy. Record all attempted candidates. This separation follows the principles in [scikit-learn's nested evaluation example](https://scikit-learn.org/0.20/auto_examples/model_selection/plot_nested_cross_validation_iris.html).

**Additional modeling and execution limitations to resolve before claiming an investable strategy**

- Markov targets are close-to-close fixed-horizon returns, while the simulator enters next open and exits using stops, state changes, flips, or a different holding horizon. Signals also subtract annualized volatility from horizon returns as a heuristic. Specify and calibrate executable outcome targets, put penalties on a documented horizon, and distinguish expected monetary return from a utility/ranking score. Changing this assumption is strategy research, not just a coding correction. See [Markov targets](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/markov/engine.py:40) and [signal scoring](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/signals/engine.py:102).
- Signal cost parameters and execution cost parameters are independent. There is no participation-rate/partial-fill model, borrowing availability/fees, crypto funding, maintenance margin, or instrument-specific lot/tick rules. Default crypto shorting is a synthetic assumption unless a specific tradable product is defined. Introduce a shared instrument/cost contract and stress assumptions before using results operationally.
- The universe is a current configured list rather than point-in-time membership, and ingestion does not model delisting outcomes. Benchmark and selection-bias controls are absent. Add suitable baselines, point-in-time membership where the research claim needs it, realistic turnover/cost stress, and dependence-aware uncertainty estimates. Adjacent multi-bar outcomes overlap; raw observation count is not an independent sample count.
- [PaperBroker](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/execution/paper.py:22) only appends in-memory events; creating a journal directory does not persist them. There is no account ledger, reconciliation, durable order IDs, retry/idempotency state machine, restart recovery, or fill adapter. Execution configuration is not wired into a running trading loop. Build these only after research correctness is established, beginning with a durable simulator and a read-only/paper adapter.
- [The mock live provider](/Users/jackmaccutcheon/Projects/Trading/TRADER2.0/src/trader_engine/data/providers.py:45) raises `NotImplementedError`; the yfinance latest-bar adapter returns the last row without proving it is a completed bar or enforcing freshness. A future live loop needs completed-bar watermarks, health monitoring, replay, and explicit stale-feed behavior.

The learned-preprocessing repair is consistent with [scikit-learn's guidance on preventing data leakage](https://scikit-learn.org/1.5/common_pitfalls.html): training-only fitting must apply to preprocessing and state construction, not just the final predictive model. The audit's specific defect evidence comes from the local code and supplied probes.
